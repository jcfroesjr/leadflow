<objective>
Close the membership lifecycle. Add the webhook REMOVE branch that marks `saiu_em`, drops the `LEAD_SAIU_GRUPO` marker, and transitions the FSM to `LEFT_GROUP`. Then change the read semantics of `_query_membership_row`/`lead_in_group`/`_probe_retry_job` so a departed lead is detected as `source='left_group'`, and make the D-1 confirmation + pre-meeting notif redirect to DM instead of an empty group.

Purpose: Today a lead who leaves the group is invisible to the system — the webhook ignores `action=remove`, the membership row stays "alive", and confirmations keep going to a group the lead abandoned. This plan makes departure a first-class event so the lead never loses their confirmation.

Output: REMOVE handler in `grupo_webhook.py`, `_mark_membership_left` + saiu_em branches in `grupo_membership.py`, DM-redirect branches in `confirmacao_agendamento.py` and `warmup_grupo.py`.

|----------|-------------|
| Evolution webhook -> backend | REMOVE event payload is unauthenticated (no signature — carried over from Phase 10 T-10-09) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Spoofing | forged action=remove webhook evicts a lead / marks saiu_em falsely | accept | Inherits Phase 10 disposition (T-10-09): Evolution webhook has no signature validation; mitigated operationally by Easypanel network isolation + instance->empresa lookup (forged event must know a valid instance name). Adding webhook signature is out of scope for this phase (would touch all 4 webhook paths). Documented as residual risk. |
| T-13-05 | Tampering | messageTimestamp -> saiu_em | mitigate | parse_evolution_timestamp falls back to utcnow() on garbage; saiu_em only used for ordering/display, not auth decisions. _mark_membership_left UPDATE is gated by WHERE saiu_em IS NULL (a replayed REMOVE affects 0 rows). |
| T-13-06 | DoS / Replay | repeated REMOVE events | mitigate | _mark_membership_left idempotent (WHERE saiu_em IS NULL → 0 rows on replay); LEAD_SAIU_GRUPO marker idempotent via conversas unique idx; FSM LEFT_GROUP is terminal (re-transition is no-op via ALLOWED_TRANSITIONS / force write is idempotent append). |
| T-13-07 | Tampering | bare @lid remove with unknown telefone | accept | bare-lid REMOVE only marks saiu_em on the lid row; no FSM change / no marker (telefone unknown). Cannot evict a phone-identified lead. Low impact. |
